深度学习训练中的 GPU 显存调度

显存是 GPU 上最稀缺的资源之一。大模型训练中，显存调度往往比算力调度更早成为瓶颈。

显存占用构成

一次训练迭代的显存大致包括：

  1. 模型参数（权重）
  2. 梯度
  3. 优化器状态（如 Adam 的 m、v）
  4. 激活值（与 batch size、序列长度正相关）

7B 参数模型在 FP16 下权重约 14GB，加上优化器与激活，单卡 24GB 往往不够——这驱动了各类显存调度技术。

软件层调度手段

梯度累积

小 batch 多次前向再统一反向，等效大 batch，降低峰值激活显存。

混合精度（AMP）

FP16/BF16 计算 + FP32 主权重，显存与带宽双省。

激活重计算（Gradient Checkpointing）

牺牲约 20% 计算，换 50%+ 激活显存节省。

ZeRO / FSDP

将优化器状态、梯度、参数分片到多卡，跨卡调度显存：

  • ZeRO-1：分片优化器状态
  • ZeRO-2：+ 梯度
  • ZeRO-3：+ 参数

DeepSpeed、PyTorch FSDP 在框架层实现这类调度，对上层仍是「一个训练 Job」，对集群则是多卡协同调度。

与视频生成的交叉

文生视频、图生视频模型（如扩散模型视频版）显存需求极高：时空维度同时膨胀。实践上常组合：

  • 序列并行 / 上下文并行
  • VAE 编码与扩散去噪分卡
  • CPU offload 部分权重

这类 pipeline 调度本质是阶段式显存预算：每个阶段只加载当前需要的子模块。

调度器视角

集群调度器除分配 GPU 数量外，还应感知 每卡显存需求。Volcano 的 nvidia.com/gpu.memory 扩展资源、以及部分云厂商的「显存型」实例 SKU，都是显存调度产品化的体现。

显存调度得当，同等硬件可多跑 2–3 倍实验并发——对研发效率影响巨大。
