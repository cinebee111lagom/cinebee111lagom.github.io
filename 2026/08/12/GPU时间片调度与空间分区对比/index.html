GPU 时间片调度 vs 空间分区调度

GPU 多任务共享有两种经典思路：时间片（轮流用整卡）和空间分区（切分硬件资源）。选型直接影响延迟、隔离与利用率。

时间片调度

多个任务交替使用同一张 GPU 的全部资源。类似 CPU 时间片，但 GPU 上下文切换成本更高：

  • CUDA Context 切换涉及显存映射、TLB 刷新
  • 切换间隙 SM 空闲，算力浪费
  • 不适合硬实时推理

CUDA MPS（Multi-Process Service） 允许多进程共享同一 Context，减少切换开销，但无显存隔离——一进程 OOM 可拖垮全部。

适用：开发调试、轻量多进程推理、批处理吞吐优先场景。

空间分区调度

将 GPU 物理或逻辑切分为多个单元，各任务绑定不同单元：

  • MIG：硬件分区，强隔离
  • vGPU（虚拟化）：Hypervisor 层切分，适合 VDI、云桌面
  • 显存 cgroup 限额（部分驱动实验特性）：软限制

适用：多租户 SaaS、SLA 敏感的在线推理、视频转码混部。

对比表

指标 时间片 / MPS 空间分区 / MIG
隔离性 弱 强
切换开销 中–高 低（实例内无切换）
资源利用率 高（弹性共享） 中（静态切片可能浪费）
配置复杂度 低 高
尾延迟 波动大 稳定

视频业务怎么选

  • 离线批转码：时间片 + 多 Stream 即可，追求吞吐
  • 直播转码 / 低延迟点播：MIG 或独立整卡，保证 P99 延迟
  • 预览缩略图生成（低优先级）：可与训练任务时间片混部，配合 K8s PriorityClass

没有银弹：很多生产集群采用 两层调度——集群层 MIG/整卡分配，进程层 Stream 流水线优化。
