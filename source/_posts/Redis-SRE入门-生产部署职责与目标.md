作为 Redis SRE，核心不是「会装 Redis」，而是让缓存/存储在**可用性、性能、成本**三角下长期稳定运行。

## SRE 职责范围

| 领域 | 内容 |
|------|------|
| 部署 | 架构选型、安装、配置基线 |
| 可用性 | 主从、哨兵、Cluster、多 AZ |
| 容量 | 内存规划、连接数、QPS 预估 |
| 可观测 | 指标、日志、追踪、告警 |
| 变更 | 升级、扩缩容、配置发布 |
| 应急 | 故障定位、回滚、复盘 |

## 生产 SLA 目标（参考）

| 指标 | 目标 |
|------|------|
| 可用性 | 99.95% ~ 99.99% |
| P99 延迟 | < 1ms（同 AZ 内网） |
| RPO | ≤ 1 分钟（AOF everysec） |
| RTO | ≤ 5 分钟（哨兵/Cluster 自动故障转移） |

## Redis 部署形态概览

```
单机 → 主从 → 哨兵（HA）→ Cluster（水平扩展）
         ↓
    K8s Operator / 云托管（ElastiCache、Redis Cloud）
```

## 与其他角色的边界

- **开发**：Key 设计、TTL、序列化格式
- **DBA/SRE**：部署、监控、备份、故障
- **安全**：网络策略、ACL、审计
