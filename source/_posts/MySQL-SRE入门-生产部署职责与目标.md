MySQL 是多数业务的核心存储，SRE 的目标是让它在**可用性、一致性、性能**之间长期稳定运行。

## SRE 职责

| 领域 | 内容 |
|------|------|
| 部署 | 架构选型、安装、参数基线 |
| 高可用 | 主从、MGR、Proxy  failover |
| 备份恢复 | 全量、增量、PITR |
| 容量 | 连接数、磁盘、QPS、buffer pool |
| 可观测 | 指标、慢日志、Performance Schema |
| 变更 | 升级、DDL、扩缩容 |
| 安全 | 权限、审计、加密、网络隔离 |

## 生产 SLA 参考

| 指标 | 目标 |
|------|------|
| 可用性 | 99.95% ~ 99.99% |
| RPO | ≤ 5 分钟（binlog 同步） |
| RTO | ≤ 15 分钟（自动/半自动切换） |
| P99 查询 | < 50ms（简单 OLTP） |

## 架构演进路径

```
单机 → 主从读写分离 → MGR / Orchestrator HA → 分库分表 + 中间件
```

## 与 DBA、开发的边界

- **开发**：表设计、索引建议、SQL 写法
- **SRE/DBA**：部署、备份、切换、监控、容量
- **安全**：合规、脱敏、访问审计
