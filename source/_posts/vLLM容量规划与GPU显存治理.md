LLM 容量核心是 **显存 = 权重 + KV Cache + 碎片/激活**，不是只看模型参数量。

## 容量模型

```
权重显存 ≈ 参数量 × 字节/参数（FP16≈2，INT4≈0.5）
KV 显存 ≈ 并发 × 层数 × 序列长 × 隐层相关常数
可用 KV ≈ 总显存 × util - 权重 - 余量
```

| 手段 | 效果 |
|------|------|
| 降 max_model_len | 显著降 KV |
| 降 max_num_seqs | 降并发占坑 |
| 量化 | 降权重 |
| TP | 权重分摊到多卡 |

## 规划流程

1. 压测得到「单实例可持续 QPS / token/s」  
2. 峰值业务量 × 安全系数 1.3~1.5  
3. 得出副本或 GPU 卡数  
4. 预留 1 个热备或快速扩容额度  

## 治理动作

| 信号 | 动作 |
|------|------|
| 长期排队 | 扩副本或升规格 |
| 显存打满偶发 OOM | 降 util/seqs/len |
| GPU util 长期 <20% | 缩容或混部（谨慎） |
| 上下文越来越长 | 单独长上下文池 |

## 周报

- 每模型：QPS、TTFT、排队、GPU 利用率  
- 预测：按增长估下季度卡数  

## 反模式

- 只按「多少亿参数」买卡
- 无压测直接估 QPS
- 长上下文与短聊天混同一池互相拖死

**显存余量建议保留 ≥8~10%** 防碎片与尖峰。
