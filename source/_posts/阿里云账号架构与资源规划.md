合理的账号与资源规划是云上 SRE 治理的基础。

## 账号模型

| 模型 | 适用 |
|------|------|
| 单账号 | 小团队、POC |
| 多账号（资源目录） | 生产推荐 |
| Landing Zone | 企业级治理 |

```
管理账号（RAM/账单/审计）
├── 生产账号（prod）
├── 预发账号（staging）
├── 开发账号（dev）
└── 安全/日志账号（audit/log）
```

## 地域与可用区

```
地域（Region）：cn-hangzhou、cn-beijing、cn-shanghai
可用区（AZ）：  同一地域内独立机房，低延迟互联
```

- 生产核心服务 **≥2 AZ**
- 数据类服务选支持跨 AZ 的产品（RDS 高可用版）

## 命名规范

```
资源类型-环境-应用-序号
例：ecs-prod-api-01
    rds-prod-order-master
    slb-prod-web
```

## 标签规范（必填）

| Key | 示例 |
|-----|------|
| env | prod / staging / dev |
| app | order-service |
| team | payment |
| cost-center | cc-1001 |
| owner | zhangsan@company.com |

## 选型决策

```
QPS < 1000，团队 < 10？
  ├─ 是 → 单地域双 AZ + 托管 RDS/Redis
  └─ 否 → ACK + 微服务 + 分账号 + 专线
```

## 资源开通流程

1. 架构评审（网络、安全、成本）
2. Terraform/ROS 模板化开通
3. 自动打标签
4. 接入 CloudMonitor 告警模板
5. CMDB 登记

架构文档应包含：账号拓扑、VPC 规划、DNS 策略、备份与 DR 方案。
