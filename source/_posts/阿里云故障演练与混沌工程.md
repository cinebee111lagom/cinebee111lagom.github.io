故障演练验证阿里云架构在真实故障下的 RTO 与 Runbook 有效性。

## 演练场景

| 场景 | 注入 | 预期 |
|------|------|------|
| 单 ECS 宕机 | 停止实例 | SLB 剔除，业务无感 |
| 单 AZ 网络 | 安全组 deny AZ 子网 | 跨 AZ 存活 |
| RDS 主备切换 | 控制台手动切换 | RPO≈0，应用重连 |
| Redis 主备切换 | 故障转移 | 短暂延迟 |
| OSS 误删 | 回收站恢复 | 数据可恢复 |
| DNS 切流 | 权重调整 | RTO 达标 |

## AZ 故障模拟（staging）

```
1. 停止 AZ-a 全部 ECS
2. 观察 SLB 健康检查
3. ESS 是否在 AZ-b 扩容
4. 记录恢复时间
```

## RDS 切换演练

```
控制台 → 主备切换
应用：连接池 test_on_borrow
验证：写读正常，延迟指标
```

## 平台级故障

```
订阅阿里云故障公告
模拟：只读模式演练（不真断 Region）
重点：Runbook 是否可执行
```

## Game Day

```
09:00  Briefing
09:30  ECS 随机 kill
11:00  RDS 切换
14:00  OSS 恢复演练
16:00  Postmortem
```

## 成功标准

- [ ] RTO ≤ SLA
- [ ] 告警 5 分钟内触发
- [ ] 无未预期数据丢失
- [ ] Runbook 可独立执行
- [ ] 改进项录入

## 注意

- 仅 staging 或可回滚窗口
- 生产 AZ 级演练需审批
- 与 **Kafka/Redis SRE** 混沌章节对照

**云 HA 不是配置完就结束，要演练**。
