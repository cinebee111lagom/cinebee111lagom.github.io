**故障演练**验证 Runbook 与监控；**混沌工程**在生产可控范围内注入故障，发现隐性依赖。

## 演练类型

| 类型 | 示例 |
|------|------|
| 桌面推演 | 无真实故障，走流程 |
| 组件故障 | 杀 ECS、RDS 主备切换 |
| 依赖故障 | 模拟 OSS/RDS 超时 |
| 全链路 | Game Day，多团队 |

## 阿里云可注入场景

```
ECS：Stop 实例、网络隔离（安全组）
RDS：主备切换（控制台/API）
SLB：摘除后端、权重为 0
ACK：kubectl delete pod、节点排水
DDoS 模拟：限流（非真实攻击）
```

## 混沌工程原则

```
1. 稳态假设（SLI 正常）
2. 最小爆炸半径（staging 先行）
3. 自动回滚
4. 生产小流量（1% 金丝雀）
```

## 工具

| 工具 | 用途 |
|------|------|
| ChaosBlade | 进程/网络/容器故障 |
| ACK 故障演练 | 节点/Pod 级 |
| 自研脚本 | API 停实例、改 SG |

## 演练流程

```
1. 目标：验证 RDS 切换 RTO < 5min
2. 范围：staging 集群
3. 观察：ARMS、SLS、告警
4. 注入：触发主备切换
5. 验证：应用错误率、恢复时间
6. 复盘：改 Runbook / 监控 / 架构
```

## 安全护栏

- 仅维护窗口或低峰
- 审批 + 值班在场
- 一键终止（恢复 SG、启动实例）
- 禁止未授权生产破坏性操作

## Checklist

- [ ] 季度至少 1 次组件演练
- [ ] 演练记录与改进项跟踪
- [ ] Runbook 与演练同步更新
- [ ] staging 与生产架构同构

**没有演练的 HA 只是配置项，不是能力**。
