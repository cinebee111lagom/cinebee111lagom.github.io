云上 DR 依赖**跨 AZ 高可用 + 跨 Region 备份 + Runbook 演练**。

## 各产品 RPO/RTO

| 产品 | 本 AZ 故障 | 跨 Region |
|------|------------|-----------|
| ECS | ESS 多 AZ 分钟级 | 镜像+快照恢复 |
| RDS | 主备切换 RPO≈0 | 跨地域备份 |
| Redis | 主备切换 | 跨地域备份 |
| OSS | 11 9 持久性 | CRR 复制 |
| ACK | 多 AZ 节点 | 异地集群+GitOps |

## RDS 跨地域备份

```
控制台 → 备份恢复 → 跨地域备份设置
目标 Region：深圳（主在杭州）
定期恢复演练到 staging 实例
```

## OSS CRR

```
源 Bucket → 跨地域复制 → DR Bucket
故障：DNS 切到 DR Region 的 Bucket/CDN
```

## 云盘快照

```
自动快照策略：每日，保留 7~30 天
核心 ECS：快照一致性组（应用静默）
```

## 整机 DR（混合）

```
云备份 Cloud Backup
  → ECS 整机备份
  → 数据库备份统一策略
  → 跨 Region 复制
```

## DR 演练（季度）

```
1. 模拟杭州 Region 不可用
2. 从深圳 RDS 备份恢复
3. OSS CRR Bucket 接管静态资源
4. DNS 切流
5. 记录 RTO，更新 Runbook
```

## 3-2-1 原则

```
3 份数据
2 种介质（云盘 + OSS）
1 份异地
```

## Checklist

- [ ] 核心库跨地域备份开启
- [ ] OSS CRR 关键 Bucket
- [ ] 季度 restore 成功
- [ ] DNS TTL ≤ 300s 便于切流

**未演练的备份等于不存在**。
