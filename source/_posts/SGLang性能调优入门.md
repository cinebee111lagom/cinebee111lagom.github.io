调优目标通常是 **更高吞吐** 或 **更低 TTFT**，二者需权衡。

## 关键旋钮

| 参数 | 影响 |
|------|------|
| context-length | 越小 KV 越省、并发越高 |
| mem-fraction-static | 提高可增容量，过易 OOM |
| tp-size | 大模型必要；小模型可能有害 |
| 量化 | 省显存 |
| 批处理并发上限 | 影响排队与延迟 |
| 前缀复用 | 固定 system prompt 提升命中 |

## 提升 Radix 命中

```
固定 system / 工具描述
模板化 RAG 前缀
避免每请求随机超长前缀
```

## 延迟 vs 吞吐

| 目标 | 做法 |
|------|------|
| 低延迟 | 降并发、充足 GPU、短上下文 |
| 高吞吐 | 提高并发、吃满 GPU、复用前缀 |

## 压测建议

- 固定模型与长度分布  
- 记录 TTFT、TPOT、token/s、GPU util  
- 一次只改一个参数  

## 反模式

- 无基线凭感觉调
- context 开到模型上限服务短聊天
- 忽略缓存命中只堆硬件
