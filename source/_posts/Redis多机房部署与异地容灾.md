单机房 Redis 扛不住机房级故障，多机房需明确 **RPO/RTO 与一致性**。

## 架构模式

### 1. 同城双活 + 异步复制

```
机房 A（主） ──异步复制──► 机房 B（从）
```

RPO：秒级；failover 手动或 Sentinel 跨机房（延迟敏感）。

### 2. 异地冷备

```
生产 Redis ──定时 RDB/AOF──► 对象存储 ──► DR 区域恢复
```

RPO：小时级；RTO：小时级；成本低。

### 3. 双写（谨慎）

应用双写两机房 Redis，一致性难，仅特殊场景。

## 网络要求

- 跨机房 RT 通常 1~30ms，复制 lag 增大
- 带宽 ≥ 峰值写入 × 副本数 × 1.2

## Cluster 跨机房

- 每机房至少 1 主 1 从，保证 slot 每机房有副本
- 避免跨机房读主（延迟）

## 演练

- 季度「机房 A 断电」演练：切流到 B
- 验证应用 Sentinel 客户端能否发现新主
- 记录实际 RTO

## 云厂商

- AWS Global Datastore、阿里云全球复制等托管方案
- SRE 重点转为监控复制 lag 与 failover 流程

多机房不是堆节点，而是**复制拓扑 + 故障切换**整体设计。
