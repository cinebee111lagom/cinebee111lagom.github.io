架构选型决定 MySQL 能撑多久、多快、多稳。

## 常见架构

| 架构 | HA | 扩展 | 复杂度 | 适用 |
|------|-----|------|--------|------|
| 单机 | 无 | 垂直 | 低 | 开发、非核心 |
| 主从 | 手动切换 | 读扩展 | 低 | 读多写少 |
| 主从 + Orchestrator | 自动 failover | 读扩展 | 中 | 中小生产 |
| MGR | 组复制自动选主 | 有限写扩展 | 高 | 强一致 HA |
| 分库分表 | 依赖上层 | 水平 | 很高 | 超大规模 |

## 读写分离

```
         ┌──────────┐
  写 ──► │  Master  │
         └────┬─────┘
    ┌──────────┼──────────┐
    ▼          ▼          ▼
 Replica1  Replica2  Replica3  ← 读（Proxy / 应用路由）
```

中间件：ProxySQL、MySQL Router、ShardingSphere。

## 选型决策

```
需要自动 failover + 强一致？
  ├─ 是 → MGR（3/5/7 节点）或 Orchestrator + 主从
  └─ 否 → 主从 + 手动切换

数据量 > 单实例 2TB 或 QPS > 万级写？
  └─ 考虑分库分表
```

## 云 RDS vs 自建

| | 云 RDS | 自建 |
|---|--------|------|
| 运维 | 低 | 高 |
| 定制 | 受限 | 完全 |
| 故障处理 | 工单/自动 | SRE 全责 |
