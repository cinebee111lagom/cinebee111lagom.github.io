推理「数据」主要是 **模型权重 + 配置 + 密钥**；会话通常不落库，但平台要能快速重建。

## 备份对象

| 对象 | 方式 |
|------|------|
| 模型权重 | 双 AZ 对象存储 / 校验副本 |
| 启动参数 | Git |
| K8s YAML | GitOps |
| API Key/证书 | Vault |
| Grafana/告警规则 | Git |

## RTO/RPO

| 场景 | RPO | RTO |
|------|-----|-----|
| 单实例挂 | 0（无状态） | ≤15 分钟拉起 |
| 机房故障 | 模型副本延迟 | ≤2~4 小时切备集群 |
| 误删模型 | 对象存储版本 | ≤1 小时恢复路径 |

## 恢复演练

```
1. 新 GPU 节点/命名空间
2. 从制品仓拉模型（校验 hash）
3. 启动同版本镜像 + 同参数
4. 跑黄金用例与压测冒烟
5. 网关切流
```

## 多活/主备

```
主集群（业务）
备集群（同模型热备或冷备）
DNS/网关一键切
```

冷备需接受加载时间；核心业务建议 **热备最小副本**。

## 反模式

- 模型只在一张本地盘
- 配置只在跳板机手改
- 从未做过空集群拉起演练

半年至少一次 **异地拉起** 演练。
