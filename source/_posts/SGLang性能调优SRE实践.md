性能调优以 **SLO 与成本** 为目标，不是无限堆并发。

## 优化杠杆

| 杠杆 | 效果 |
|------|------|
| 并发 / batch | 提吞吐，过则伤延迟 |
| 量化 | 降显存、提可并发 |
| TP 规模 | 大模型必选，过大会通信开销 |
| Radix 前缀共享 | 降重复 prefill |
| 上下文长度上限 | 控 KV |
| 结构化约束 | 可能降速，需单独基线 |
| 路由亲和 | 提高缓存命中 |

## 调优循环

1. 固定压测集（短 Chat / 长上下文 / JSON 输出）  
2. 改一个变量  
3. 看 TTFT、TPOT、token/s、错误率、GPU  
4. 达标则固化基线  

## 常见瓶颈

| 现象 | 可能原因 |
|------|----------|
| TTFT 高 | 排队、长 prompt、冷缓存 |
| 吞吐低 | 并发过低、卡未吃满 |
| OOM | len/seqs/util 过大 |
| 命中率低 | 副本过多打散、prompt 不稳定 |

## 反模式

- 无对照实验乱改参数  
- 用玩具 prompt 宣称「已优化」  
- 忽略结构化场景单独压测
