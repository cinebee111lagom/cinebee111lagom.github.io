演练证明 Runbook 可执行，而不是「文档看起来对」。

## 演练场景

| 场景 | 期望 |
|------|------|
| 杀一个副本 | LB 摘流，错误率短暂可控 |
| 节点 NotReady | Pod 迁移，服务恢复 ≤ RTO |
| 人为 OOM | 限流/降并发生效 |
| 坏镜像滚动 | 可回滚 |
| 网关限流打开 | 核心租户仍可用 |
| 缓存冷启动 | TTFT 抖动在预期内 |
| 依赖存储只读/延迟 | 有告警与降级策略 |

## 实施原则

1. 先预发，再生产小流量窗口  
2. 有观察员 + 一键回滚人  
3. 记录：注入点、现象、耗时、缺口  
4. 演练后改告警阈值与文档  

## 混沌注意

- GPU 节点演练要申请窗口，避免误伤共享池  
- TP 多卡：注入应针对整组，而非随机抽一张卡却期望仍服务  
- 不要在未知高峰做首次演练  

## 反模式

- 只演「重启 Pod」一种  
- 演练无指标对比  
- 发现问题不改 Runbook  

**每季至少覆盖：实例故障、过载、回滚 三类。**
