生产启动参数应 **入库、可复现、经压测**，避免口头口令。

## 基线清单（按版本核对官方参数名）

| 类别 | 关注点 |
|------|--------|
| 模型路径 | 本地/PVC，禁止生产临时下载 |
| 并行 | `--tp-size` / 相关 TP 配置 |
| 显存 | mem fraction / 预留比例 |
| 上下文 | max 上下文长度 |
| 并发 | 最大运行请求数 |
| 端口 | HTTP / metrics |
| 安全 | API Key、禁用无关调试口 |

## 调参顺序

1. 先保证能稳定加载模型（无 OOM）  
2. 压测短上下文，定并发与吞吐上限  
3. 再开长上下文与结构化场景  
4. 观察 Radix 命中率，微调池化与路由  

## 变更原则

| 原则 | 说明 |
|------|------|
| 一次只改一类 | 便于归因 |
| 灰度 | 先 1 副本或金丝雀 |
| 回滚包 | 旧镜像 + 旧参数 ConfigMap |
| 记录 | 变更单写清预期指标 |

## 反模式

- 生产直接拉最新 nightly
- 把开发机「能跑」参数原样上线
- 无压测把并发拉满

**基线 = Git 里的启动脚本 + 压测报告链接**。
