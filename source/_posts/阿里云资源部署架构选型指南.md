阿里云架构选型需结合业务 SLA、合规、成本与团队能力。

## 常见架构

| 架构 | 适用 | 优点 | 缺点 |
|------|------|------|------|
| 单 AZ ECS + RDS | 开发/低 SLA | 简单便宜 | 无 AZ 容灾 |
| 多 AZ + SLB | 生产 Web/API | 高可用 | 需设计无单点 |
| ACK 容器 | 微服务、弹性 | 扩缩容快 | 运维复杂 |
|  Serverless（FC/SAE） | 事件、轻量 API | 免运维 | 冷启动、限制 |
| 混合云 | 合规、存量 | 渐进迁移 | 网络复杂 |

## 典型三层 Web

```
用户 → CDN/WAF → ALB（多 AZ）
              → ECS/ACK Pod（多 AZ）
              → RDS 主备（同 Region 跨 AZ）
              → Redis 集群版
              → OSS（静态/备份）
```

## Region 与 AZ

| 概念 | 说明 |
|------|------|
| Region | 地域（如 cn-hangzhou） |
| AZ | 可用区（如 cn-hangzhou-h/i/j） |
| 跨 AZ | 同城容灾，延迟低 |
| 跨 Region | 异地灾备，延迟高 |

## 选型决策

```
需要 K8s 且团队有能力？
  ├─ 是 → ACK 托管版 + Terway
  └─ 否 → ECS + SLB + 弹性伸缩
         数据库优先 RDS 而非自建
```

## 产品替代原则

| 自建 | 托管推荐 |
|------|----------|
| MySQL on ECS | RDS / PolarDB |
| Redis on ECS | 云 Redis |
| Kafka on ECS | 消息队列 Kafka 版 |
| 文件存储 | OSS / NAS |

## 版本与规格

- ECS：生产推荐 **g8i/c8i** 新一代，按量+预留混合
- RDS：高可用系列 + 跨 AZ

架构文档应包含：网络拓扑、账号划分、Tag 规范、RPO/RTO、成本预算。
