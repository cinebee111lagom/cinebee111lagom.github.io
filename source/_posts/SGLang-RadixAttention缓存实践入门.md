把 **前缀设计** 做好，RadixAttention 才能真正提速降本。

## 哪些前缀值得固定

| 内容 | 建议 |
|------|------|
| System 人设 | 固定文本 |
| 工具/函数说明 | 固定模板 |
| RAG 指令头 | 固定，文档放后面 |
| 多轮历史 | 越靠前越可能共享 |

## 好的请求结构

```
[固定 system][固定工具说明][可变用户问题][可变检索片段]
```

尽量让可变部分靠后。

## 观察命中

- 看 metrics 中与 cache/hit 相关的指标（版本而异）  
- 对比：随机 system vs 固定 system 的 TTFT  
- 压测时模拟真实多用户共享同一人设  

## 业务改造

1. 配置中心下发统一 system prompt  
2. 模板版本化，避免频繁微调措辞  
3. Agent 工具列表稳定更新，变更走发布  

## 反模式

- 每请求拼接时间戳/随机 ID 到最前面
- 把整本知识库塞进前缀
- 多租户人设完全不同却期望高命中（应分池或接受低命中）

缓存是 **产品+工程** 共同优化点。
