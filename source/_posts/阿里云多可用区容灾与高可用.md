阿里云高可用靠**多 AZ 部署 + 托管产品 HA + 跨 Region DR** 三层保障。

## 同 Region 多 AZ

```
SLB/ALB：多 AZ 实例
ECS：ESS 跨 AZ 均衡
RDS：双 AZ 主备
Redis：主备跨 AZ
ACK：节点池 spread 跨 AZ
```

```
应用无 AZ 亲和 → 任一 AZ 故障自动切流
```

## 跨 Region DR

```
主：cn-hangzhou
备：cn-shenzhen

RDS/OSS：跨地域备份/CRR
应用：双 Region 部署 或 冷备
DNS：健康检查切换
```

## RPO/RTO 目标

| 层级 | RPO | RTO |
|------|-----|-----|
| AZ 故障 | 0~分钟 | 自动 |
| Region 故障 | 分钟~小时 | 1~4h（演练） |

## 切流 Runbook

```
1. 确认 Region 级故障（官方公告+监控）
2. 提升 DR Region RDS（备份恢复或只读提升）
3. OSS/CDN 切 DR Bucket
4. DNS 权重切到深圳
5. ACK 或 ECS 启动 standby 栈
6. 验证核心链路
```

## 混沌演练

```
- 手动停止单 AZ 全部 ECS（staging）
- 验证 SLB 健康检查与 ESS
- RDS 主备切换事件回顾
```

## 避免单点

| 单点 | 解决 |
|------|------|
| 单 AZ 部署 | 强制多 AZ 策略 |
| 单 NAT | NAT 网关多 AZ |
| 单 DNS | DNS 负载均衡 |
| 手工配置 | IaC + GitOps |

## Checklist

- [ ] 生产全链路跨 ≥2 AZ
- [ ] 跨 Region 备份开启
- [ ] 年度 Region 级 DR 演练
- [ ] DNS TTL 与切流文档

**单 AZ 是技术债，不是省钱方案**（核心系统）。
