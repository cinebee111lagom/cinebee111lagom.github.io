告警要 **少而准**，每条绑定 Runbook。

## 分级

| 级别 | 含义 | 响应 |
|------|------|------|
| P0 | 服务不可用 / 大面积失败 | 立即处理 |
| P1 | SLO 明显劣化 | 15 分钟内响应 |
| P2 | 趋势异常 / 容量预警 | 值班日处理 |
| P3 | 信息类 | 周会复盘 |

## 推荐告警（示意）

| 告警 | 级别 | 思路 |
|------|------|------|
| 实例 Down / 探活失败 | P0 | 持续 N 分钟 |
| 5xx 飙升 | P0/P1 | 对比基线 |
| TTFT P99 超阈 | P1 | 区分短/长上下文 |
| 队列持续堆积 | P1 | 过载或下游慢 |
| GPU OOM / 重启风暴 | P0 | 查并发与 len |
| 缓存命中骤降 | P2 | 路由/副本变更？ |
| 显存长期打满 | P2 | 容量规划 |

## 值班手册要点

1. 告警 → 看面板确认范围（单实例 or 全集群）  
2. 查近期变更（镜像、模型、参数、网关）  
3. 按 Runbook 止血（限流、扩容、回滚）  
4. 记录时间线，事后补 RCA  

## 反模式

- 阈值告警无静默，值班麻木  
- 告警无负责人、无链接  
- 把「缓存命中波动」一律当 P0

**每条告警必须能回答：谁处理、先做什么、如何升级。**
