切分的核心目标之一是**显存隔离**：防止「邻居 OOM 拖垮我」。

## 各方案隔离能力

| 方案 | 显存隔离 | 算力隔离 | OOM 影响范围 |
|------|----------|----------|--------------|
| 整卡 | 完全 | 完全 | 仅本进程 |
| MIG | 硬件硬限 | 硬件份额 | 仅本实例 |
| MPS | 无 | 时间片共享 | **全部客户端** |
| vGPU | profile 上限 | 时间片 + 权重 | 同物理卡 VM |

## MIG 显存硬限

MIG 实例创建时显存固定，例如 `1g.10gb` 严格 10GB：

```bash
nvidia-smi -i 0 -gi 0 -dci  # 查看实例 0 显存
```

容器内 `cudaMemGetInfo` 返回的 free/total 即为实例配额，**无法突破**。

## QoS 维度

除显存外，还需关注：

1. **算力份额**：MIG SM 分区保证最小算力
2. **PCIe 带宽**：多实例共享，大图传输可能竞争
3. **NVLink**：多卡场景下实例间通信路径
4. **编码引擎**：NVENC 会话数 per instance

## 软限 vs 硬限

| | 硬限（MIG） | 软限（cgroup/实验特性） |
|---|------------|------------------------|
|  enforcement | 硬件 | 驱动/内核 |
| 可靠性 | 高 | 中 |
| 灵活性 | 低 | 高 |

生产多租户优先 **MIG 硬限**。

## 最佳实践

- 模型加载前评估 peak 显存，选 profile 留 15% 余量
- 禁止 MPS 混部 SLA 敏感服务
- 监控每实例 `fb_used / fb_total`，接近 90% 告警

显存隔离是 GPU 切分价值的**底线**，MIG 是目前最可靠的实现。
