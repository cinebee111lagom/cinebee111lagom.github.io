GPU 扩缩贵且慢，**过载保护优先于盲目自动扩容**。

## 扩缩策略

| 策略 | 适用 |
|------|------|
| 手工/定时扩容 | 活动高峰已知 |
| 基于队列/QPS 告警扩容 | 半自动 |
| HPA + 自定义指标 | 小模型多副本 |
| 不自动缩到 0 | 避免冷启动过久 |

## 扩容成本

- 拉起时间 = 调度 + 镜像 + **模型加载**  
- 新副本缓存冷，短时 TTFT 可能变差  
- TP 大模型扩容单位是「一组卡」  

## 过载保护

| 手段 | 作用 |
|------|------|
| 网关限流 / 并发上限 | 保存活 |
| 返回 429 | 让客户端退避 |
| 队列长度熔断 | 防止无限堆积 |
| 降级 | 切小模型 / 关非核心路由 |

## 建议阈值

1. 定义最大可接受排队与 TTFT  
2. 达阈先限流，再扩容  
3. 扩容后观察 10~30 分钟再决定是否继续  

## 反模式

- 无上限自动扩导致账单爆炸  
- 过载时只重启不限流  
- 缩容过猛，高峰再冷启动翻车  

**过载时优先保护「已在途请求」与核心租户。**
