推理服务灾备重点是 **配置与制品可恢复**，不是备份 KV Cache。

## 要备份什么

| 项 | 方式 |
|----|------|
| 启动参数 / ConfigMap | Git |
| Secret 元数据与轮换流程 | 保险箱 + Runbook |
| 镜像 digest 列表 | 制品库 |
| 模型权重 | 对象存储多副本 / 跨区 |
| 网关路由与配额 | GitOps |
| 监控告警规则 | Git |

## 不必备份

- 实例内存中的 Radix/KV 缓存（可重建）  
- 瞬时队列状态  

## DR 场景

| 场景 | 恢复 |
|------|------|
| 单 Pod 挂 | 调度重建，模型本地/PVC |
| 节点丢失 | 换节点 + 模型预热 |
| 机房故障 | 切备集群 / 备池 |
| 误发坏版本 | 回滚镜像与参数 |

## RTO 优化

- 模型预热到本地盘或高速 PVC  
- 镜像预拉取  
- 备池 hot standby（贵但快）  

## 反模式

- 只备份虚机整盘、不版本化配置  
- 密钥无人能转（单点保管）  
- 从未演练过「换区拉起」  

**每季度至少一次：从文档零开始拉起一套可服务集群。**
