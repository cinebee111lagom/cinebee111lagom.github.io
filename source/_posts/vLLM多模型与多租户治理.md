多业务共用推理平台时，用 **分池 + 配额 + 路由** 避免互相拖垮。

## 分池模式

| 池 | 示例 |
|----|------|
| chat-7b | 通用对话，多副本 |
| coder-32b | 代码，TP=2 |
| longctx | 长上下文专用 |
| batch | 离线批处理，低优先级 |

每个池独立 Deployment / 启动参数 / 告警。

## 网关路由

```
Authorization → 租户
model 字段   → 后端池
配额         → RPM/TPM
```

禁止租户直接指定任意内部模型名（可用别名映射）。

## 配额

| 维度 | 控制 |
|------|------|
| RPM | 每分钟请求 |
| TPM | 每分钟 token |
| 并发 | 进行中请求数 |
| 日预算 | 成本封顶 |

超限返回 429，带 `Retry-After`。

## LoRA 多租户

共享 base + 多 LoRA 可降成本，但需限制 `max_loras`，并隔离适配器来源审核。

## 反模式

- 所有模型一个进程硬塞
- 无 429，直接打爆 GPU
- 租户共享同一 API key

租户开通走 **工单：模型、配额、SLA**。
