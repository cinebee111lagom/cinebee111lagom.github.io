一块 A100 80GB 整卡分配给单个推理服务，可能只用 2GB 显存——**资源浪费**。GPU 切分（Partitioning）把物理卡拆成多个逻辑单元，让多任务**安全共享**。

## 不切分的问题

| 问题 | 后果 |
|------|------|
| 整卡独占 | 小任务占满配额，集群利用率低 |
| 多进程抢卡 | 显存 OOM 互相拖垮 |
| 多租户混部 | 无法保证 SLA，尾延迟抖动 |
| 成本 | 云 GPU 按卡计费，利用率低 = 烧钱 |

## 切分的三个层次

```
┌─────────────────────────────────────┐
│  硬件切分（MIG / vGPU profile）      │  强隔离
├─────────────────────────────────────┤
│  驱动切分（MPS / 时间片）            │  弱隔离，高灵活
├─────────────────────────────────────┤
│  编排切分（K8s MIG / 显存限额）      │  集群层配额
└─────────────────────────────────────┘
```

## 典型场景

- **推理多租户**：10 个模型各占 1–4GB，一张 A100 切 7 路 MIG
- **视频转码**：每路 NVENC 占固定算力，MIG 硬隔离
- **开发测试**：MPS 多进程共享，成本低
- **云桌面 / 云游戏**：vGPU 按 profile 分配

## 与「调度」的区别

- **调度**：决定任务跑在哪张卡（集群层）
- **切分**：决定一张卡如何分给多个任务（设备层）

二者配合：K8s 调度器分配 MIG 实例 → 容器内看到独立 GPU。
