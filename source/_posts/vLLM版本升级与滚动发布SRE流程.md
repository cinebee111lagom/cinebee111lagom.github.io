vLLM、CUDA、模型权重任一变更都可能影响 **质量与性能**，必须可回滚。

## 变更类型

| 类型 | 风险 | 策略 |
|------|------|------|
| 镜像小版本 | 中 | staging → 金丝雀 → 全量 |
| 大版本 | 高 | 完整回归 + 压测 |
| 换模型权重 | 高 | 评测集 + A/B |
| 仅参数 | 中 | 可热重启滚动 |

## 滚动流程（多副本）

```
1. 备份当前启动参数与镜像 tag
2. staging 跑：健康检查 + 黄金用例 + 压测对比
3. prod 先 1 个副本升级
4. 观察 TTFT/错误率 30~60 分钟
5. 其余副本滚动
6. 异常 → 回滚镜像 tag
```

## 大模型 TP 单副本

```
1. 维护窗口或备池接流量
2. 停旧 → 启新（同 GPU 组）
3. readiness 通过后切回
4. 保留旧镜像 7 天
```

## 回归清单

- [ ] `/v1/models` 名称不变（或网关映射）
- [ ] 流式 SSE 正常
- [ ] 关键评测集分数无明显下降
- [ ] TTFT/吞吐不低于基线 90%
- [ ] 显存占用符合预期

## 反模式

- latest 标签直接上生产
- 换模型不通知业务方
- 无回滚镜像
