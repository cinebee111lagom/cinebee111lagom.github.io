多模型共集群时，故障与吵闹邻居是常态，要用 **分池 + 配额** 治理。

## 分池原则

| 池 | 建议 |
|----|------|
| 核心业务 | 独立 GPU、独立告警 |
| 实验/评测 | 隔离，可抢占 |
| 长上下文 | 单独池，避免拖死短 Chat |
| 结构化重负载 | 单独评估容量 |
| 多模态 | 独立显存与超时 |

## 多租户控制

- 每租户：密钥、QPS、并发、可访问 model 列表  
- 成本：按 token / GPU 时间记账  
- 优先级：网关侧实现，避免后端无脑 FIFO 被刷爆  

## 路由

```
model=chat-7b  → pool-chat
model=code-32b → pool-code-tp2
model=vl-7b    → pool-vl
```

## 缓存与租户

- 不同租户 system prompt 不同 → 命中率自然隔离  
- 同租户大量共享前缀 → 可考虑亲和路由提升命中  

## 反模式

- 所有模型塞一个巨型进程  
- 实验流量与核心共用无配额  
- 租户之间可互相枚举 model  

**治理目标：吵闹邻居可限流、可隔离、可计量。**
